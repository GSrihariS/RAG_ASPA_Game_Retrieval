# Data

All data and results for the project. Unpack `data.zip` next to `code/`; the code finds these files
through `code/paths.py`.

| Assignment item | Location |
|---|---|
| Knowledge base | `knowledge_base/` |
| Queries | `evaluation_dataset/queries.jsonl` |
| Retrieved results | `retrieval_results/sample_queries/`, `retrieval_results/eval/runs.json` |
| Evaluation dataset | `evaluation_dataset/eval.xls`, `evaluation_dataset/steam_annotations_confirmed.json` |
| Annotation agreement (Q4) | `evaluation_dataset/iaa_report.json`, `evaluation_dataset/steam_annotations_iaa.json` |
| Retrieval metrics (Q3) | `retrieval_results/eval/` |
| Generation benchmark (Q4) | `generation_results/input.jsonl`; final references in `code/generation/rag_summary/data/generation_annotations/` |
| Generated answers (Q4) | `generation_results/results/generation_results.json`, `generation_results/results/predictions.jsonl` |
| Downstream metrics and ablation study (Q4, Q5) | `generation_results/results/`; final scores in `code/generation/rag_summary/experiments/final/` |

## knowledge_base/

10,000 Steam reviews from 20 games, 500 per game. See its own [README](knowledge_base/README.md), plus
[DATA_FORMAT.md](knowledge_base/DATA_FORMAT.md) for every field and
[PROCESSING.md](knowledge_base/PROCESSING.md) for the cleaning and chunking rules.

| Count | Value |
|---|---|
| Source reviews | 10,000 |
| Retained documents | 9,781 |
| Retained words | 823,461 |
| Retained word types (lowercase) | 22,827 |
| Chunks in `processed/chunks.jsonl` | 12,822 |
| Chunks in the indexes | 12,813 |

The two chunk counts differ because 9 chunks have empty text, and the index builders skip them.

## evaluation_dataset/

| File | Content |
|---|---|
| `steam_annotations_confirmed.json` | 1,000 human-annotated chunks, 50 from each of the 20 games |
| `eval.xls` | The same annotations as a table, generated by `code/eval/export_eval_xls.py` |
| `steam_annotations_iaa.json` | The same 1,000 chunks with `annotator_1` and `annotator_2` sentiment codes for the 8 aspects, from two review passes |
| `iaa_report.json` | Agreement results, generated by `code/data_pipeline/calculate_iaa.py` |
| `queries.jsonl` | 100 retrieval queries; the fields are described in `code/eval/README.md` |
| `dataset_stats.md` | Label statistics, generated by `code/eval/dataset_stats.py` |

`eval.xls` has one row per chunk and aspect (1,000 chunks x 8 aspects = 8,000 rows):

| Column | Meaning |
|---|---|
| `sample_id`, `chunk_id` | Annotation ID and the chunk's ID in the knowledge base |
| `game_name`, `text` | Game and chunk text |
| `aspect` | story, graphics_visuals, gameplay, controls, performance, audio, bugs_stability or online_multiplayer |
| `subjectivity` | Opinionated, Objective or empty. Always empty when the aspect is not mentioned; also empty for 37 of the 2,898 mentions |
| `sentiment` | Positive, Negative, Mixed, Neutral, Unclear or Not mentioned |
| `evidence` | Text span that supports the label, or empty. Always empty when the aspect is not mentioned; also empty for 406 of the 2,898 mentions |

Reported two-pass labels are in `steam_annotations_iaa.json`. Exact passage agreement is
**98.2% (982/1,000 passages)**, aspect-label agreement is 99.775% and Cohen's kappa is 0.996; full results are
in [iaa_report.json](evaluation_dataset/iaa_report.json). These figures cover sentiment only. The file records
the differences between the two passes as reported afterwards, not independent first-pass labels
(`independent_pre_review_annotations: false`).

## indexes/

Prebuilt from `knowledge_base/processed/chunks.jsonl`. `sparse/` is a BM25 index (bm25s, k1 = 1.5,
b = 0.75); `dense/` is a FAISS inner-product index over normalized `BAAI/bge-small-en-v1.5` embeddings.

## retrieval_results/

- `eval/`: judgments, rankings, metrics and report of the 100-query evaluation.

## generation_results/

Outputs of the RAG summarization experiment: 100 fixed questions answered with `deepseek-v4-pro` by
four methods (`baseline`, `improved`, `verify_delete`, `verify_revise`). 398 of the 400 tasks completed;
`verify_delete` and `verify_revise` each failed one.

| File | Content |
|---|---|
| `input.jsonl` | The 100 questions, each with its saved `hybrid_rerank` review passages |
| `results/generation_results.json` | Output of all 400 tasks: generated answer, per-task metrics and execution time |
| `results/predictions.jsonl` | The 398 completed answers with the fact IDs each one selected |
| `results/evaluation_references.jsonl` | The reference fact sets used for these scores |
| `results/report.md`, `results/summary.csv`, `results/report_data.json` | Metrics per method |
| `results/manifest.json` | Model, settings, and prompt and code hashes |

The scores in this folder use the references from before the human review.
`code/generation/rag_summary/experiments/final/` holds the same generated answers rescored against the
final references (`human_review_v1`), so its numbers differ. Use those as the final scores:

| Method | Completed | Precision | Recall | F1 | Unit recall | Contrast coverage | Latency (s) |
|---|---:|---:|---:|---:|---:|---:|---:|
| `baseline` | 100 | 85.40 | 72.71 | 75.82 | 88.73 | 56.25 | 3.12 |
| `improved` | 100 | 88.03 | 69.68 | 75.12 | 87.18 | 50.00 | 4.81 |
| `verify_delete` | 99 | 89.49 | 68.67 | 74.74 | 87.05 | 50.00 | 11.76 |
| `verify_revise` | 99 | 89.20 | 69.58 | 75.23 | 87.05 | 50.00 | 12.04 |

Scores are percentages, macro-averaged across applicable questions. `report.md` in that folder also has the
paired F1 comparisons between methods, with bootstrap confidence intervals.

The final references are in `code/generation/rag_summary/data/generation_annotations/`: 2,898 review-aspect facts
from the 1,000 annotated chunks, 591 required query-fact pairs, and 40 human review decisions.

The metrics are fact-selection precision, recall and F1, coverage-unit recall, polarity-contrast coverage
and latency. Faithfulness, answer relevance and context relevance are not included.

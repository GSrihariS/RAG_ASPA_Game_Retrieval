## knowledge_base/

10,000 Steam reviews from 20 games, 500 per game. See its own [README](knowledge_base/README.md), plus
[DATA_FORMAT.md](knowledge_base/DATA_FORMAT.md) for every field and
[PROCESSING.md](knowledge_base/PROCESSING.md) for the cleaning and chunking rules.

| Count | Value |
|---|---|
| Source reviews | 10,000 |
| Retained documents | 9,781 |
| Retained words | 823,461 |
| Retained word types (lowercase) | 22,827 |
| Chunks in `processed/chunks.jsonl` | 12,822 |
| Chunks in the indexes | 12,813 |

The two chunk counts differ because 9 chunks have empty text, and the index builders skip them.

| `rag_summary_approved_references.jsonl` | 100 human-reviewed English reference summaries with evidence hashes |

`eval.xls` has one row per chunk and aspect (1,000 chunks x 8 aspects = 8,000 rows):

| Column | Meaning |
|---|---|
| `sample_id`, `chunk_id` | Annotation ID and the chunk's ID in the knowledge base |
| `game_name`, `text` | Game and chunk text |
| `aspect` | story, graphics_visuals, gameplay, controls, performance, audio, bugs_stability or online_multiplayer |
| `subjectivity` | Opinionated, Objective or empty. Always empty when the aspect is not mentioned; also empty for 37 of the 2,898 mentions |
| `sentiment` | Positive, Negative, Mixed, Neutral, Unclear or Not mentioned |
| `evidence` | Text span that supports the label, or empty. Always empty when the aspect is not mentioned; also empty for 406 of the 2,898 mentions |

Reported two-pass labels are in `steam_annotations_iaa.json`. Exact passage agreement is
**98.2% (982/1,000 passages)**, aspect-label agreement is 99.775% and Cohen's kappa is 0.996; full results are
in [iaa_report.json](evaluation_dataset/iaa_report.json). These figures cover sentiment only. The file records
the differences between the two passes as reported afterwards, not independent first-pass labels
(`independent_pre_review_annotations: false`).

The generation benchmark contains 40 single-aspect, 34 aspect-and-sentiment, 14 multi-aspect and
12 cross-game questions. The two few-shot examples (`q06` and `q24`) come from the development set;
the final experiment evaluates the 80 test questions. All five `rag_summary_` files are stored directly
in `evaluation_dataset/` and are required to reproduce the experiment.

## indexes/

Prebuilt from `knowledge_base/processed/chunks.jsonl`. `sparse/` is a BM25 index (bm25s, k1 = 1.5,
b = 0.75); `dense/` is a FAISS inner-product index over normalized `BAAI/bge-small-en-v1.5` embeddings.

### Final experiment: `rouge_results/`

The experiment uses `deepseek-v4-pro` and compares a 2 x 2 design: few-shot prompting on/off and
context compression on/off. Few-shot methods receive the same two development examples. Compression
uses query-aware TF-IDF sentence selection with a target text-retention ratio of 0.75.

| Method | Few-shot examples | Context compression |
|---|---|---|
| `baseline` | No | No |
| `few_shot` | Yes | No |
| `compressed` | No | Yes |
| `combined` | Yes | Yes |

There are 80 test questions and one repeat, giving 320 tasks. The run completed 315 tasks and recorded
5 failures. It used concurrency 20 and up to two retries after the initial attempt: 333 model requests
and 13 retries in total. Generation took 73.79 seconds, with 1,268,578 input tokens and 92,710 output tokens.

| File in `rouge_results/` | Content |
|---|---|
| `input.jsonl` | The 80 test questions and their fixed review evidence |
| `generation_results.json` | All 320 task records, including cited answers, scores, failures and request traces |
| `predictions.jsonl` | The 315 completed predictions |
| `evaluation_references.jsonl` | Reviewed English reference summaries for the 80 test questions |
| `split.json`, `few_shot_examples.json` | The frozen split and the two examples used in this run |
| `summary.csv` | Aggregate scores, token use, latency and completion counts by method |
| `report.md`, `report_data.json` | Results, paired comparisons, bootstrap confidence intervals and factorial interactions |
| `manifest.json` | Model settings, compression ratio, reference version, and prompt, code and data hashes |
| `run_summary.json` | Task counts, request totals, retries and total generation time |
| `checkpoint.jsonl` | Task records written as the experiment progresses |

ROUGE-1, ROUGE-2 and ROUGE-L are computed locally against the human-reviewed English summaries.
Citation markers are removed before scoring; text is lowercased and tokenized without stemming.
ROUGE-L uses the longest common subsequence over the whole answer. The table reports macro-averaged
F1 scores and mean input tokens, latency and text retention over completed answers.

| Method | Completed / 80 | ROUGE-1 F1 (%) | ROUGE-2 F1 (%) | ROUGE-L F1 (%) | Input tokens | Latency (s) | Text retained (%) |
|---|---:|---:|---:|---:|---:|---:|---:|
| Baseline | 79 | 28.41 | 8.63 | 19.05 | 3,277 | 3.96 | 100.0 |
| Few-shot | 79 | 29.42 | 10.38 | 20.54 | 4,667 | 4.45 | 100.0 |
| Compression | 78 | 27.63 | 9.04 | 19.15 | 2,972 | 4.00 | 74.8 |
| Few-shot + compression | 79 | 28.97 | 10.23 | 20.39 | 4,508 | 4.61 | 74.8 |

Few-shot prompting achieves the highest ROUGE scores. Relative to baseline, its paired ROUGE-2 F1
gain is **1.75 percentage points** (95% bootstrap CI: **0.95 to 2.57**) and its ROUGE-L F1 gain is
**1.49 points** (95% CI: **0.49 to 2.50**), over 79 paired questions. The intervals use 5,000 bootstrap
resamples with seed 42.

Compression retains about 74.8% of the evidence text and reduces mean input tokens by **9.4%** over
the 78 questions completed by both compression and baseline, while ROUGE-2 and ROUGE-L remain close
to baseline. Combining compression with few-shot prompting retains most of the few-shot gain and
uses fewer input tokens than few-shot alone. ROUGE precision and recall are also included in `summary.csv`.

### Recompute the final scores

Run from `code/`, using a new output directory:

```bash
python generation/rag_summary/evaluate_generation.py ../data/generation_results/rouge_results --output ../data/generation_results/rouge_rescored
```

This validates the saved evidence and recomputes ROUGE without an API key or an evaluation model.
The generation code and prompts are in `code/generation/rag_summary/`; benchmark data and reviewed
references are the five `rag_summary_` files in `data/evaluation_dataset/`.
